# Findings

## Active task path updates bypass reservation checks

- **Impact:** A task can remain assigned, submitted, or changes-requested while its edit/create paths are changed to overlap another active task's reservation. This breaks exclusive write ownership after assignment and can allow concurrent workers to edit the same path.
- **Location/evidence:** `src/SubagentDrivenDevelopment/Services/TaskService.ts:124-158` updates `editPaths` and `createPaths` on the current task without restricting active task status or checking other reservations. The new guard at `TaskService.ts:368-394` runs only from `assign`, so it does not protect this update path.
- **Required correction:** Prevent edit/create scope changes while a task is active, or otherwise validate scope changes against all other active reservations within the same transaction. Add a regression test that attempts an overlapping scope update after assignment and verifies it is rejected without changing the ledger.
- **Blocking:** Yes.

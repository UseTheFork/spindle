# Complete tickets through task execution

- **Reporter:** User
- **Category:** enhancement
- **Author:** Copilot

## Requirements

Integrate task execution with the ticket workflow. Require a task plan before implementation starts. The controller starts or resumes the ticket worktree, coordinates task workers there, commits the combined changes after all tasks are accepted, and submits one ticket-level implementation report. Prevent ticket submission and completion while any task is not accepted. Preserve ticket-level checks, review, integration, and post-merge validation as the final gates. Update operator and implementer guidance and record the changed ticket commit-ownership decision. Do not add general migration or compatibility support for prior ledger versions; convert this feature workspace's active ledger once as the rollout exception agreed in its spec.

## Acceptance Criteria

- When a controller attempts to start implementation for a ticket without a task plan, the system shall reject the request and explain that tasks must be defined first.
- While any task is unassigned, assigned, submitted, or changes-requested, the system shall prevent ticket-level implementation submission and ticket completion.
- When all tasks are accepted, the controller shall be able to submit one ticket-level implementation report for the combined commit.
- After ticket-level implementation submission, the existing ticket-level checks, review, integration, and post-merge validation shall remain required.
- When the new ledger schema is introduced, the system shall convert this feature's active ledger once without accepting other prior ledger versions.
- The project guidance shall explain controller-owned commits, shared ticket worktrees, task reports, and the task-before-ticket completion sequence.

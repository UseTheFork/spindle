# Coordinate parallel tasks

- **Reporter:** User
- **Category:** enhancement
- **Author:** Copilot

## Requirements

Coordinate task readiness and concurrent assignments within one ticket worktree. A task may be assigned only when each dependency is accepted and its edit/create paths do not overlap paths reserved by another active task. Assigned, submitted, and changes-requested tasks retain exclusive reservations for their edit/create paths. Accepted tasks release their reservations. Reference paths do not reserve files. Do not introduce manual task blockers or task-specific check requirements.

## Acceptance Criteria

- When a task depends on another task that is not accepted, the system shall keep it unavailable for assignment.
- When a task's edit/create paths overlap those of an assigned, submitted, or changes-requested task, the system shall reject its assignment and identify the conflicting task and path.
- When active tasks have disjoint edit/create paths but share reference paths, the system shall allow both tasks to be assigned.
- When a task is accepted, the system shall release its edit/create path reservations.
- When task dependencies contain a cycle, the system shall reject the dependency change.
- When all dependencies are accepted and no active file-scope conflicts exist, the system shall allow the task to be assigned.

# Dispatch tickets with pending records

- **Reporter:** User
- **Category:** enhancement
- **Author:** Copilot

## Requirements

Ticket dispatch shall use the committed code and authoritative requirements as its baseline while permitted, unstaged workflow bookkeeping remains pending in the feature worktree. Dispatch shall not commit pending bookkeeping. Changes to code or requirements, staged index content, or other unsafe worktree state shall stop dispatch with an actionable error and preserve existing work.

## Acceptance Criteria

- While only permitted workflow bookkeeping is pending, when a ticket is dispatched, the system shall create no record-only commit and shall base the ticket worktree on the committed feature HEAD.
- Dispatch shall allow pending ledger and report changes and ticket-file changes only when the Requirements and Acceptance Criteria remain unchanged.
- Dispatch shall stop with an actionable error and preserve existing work when code, authoritative requirements, or the index is changed, or when untracked non-record content is present.
- Tests shall verify that permitted pending records survive dispatch and unsafe worktree state is rejected.

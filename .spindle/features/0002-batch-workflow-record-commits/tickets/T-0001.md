# Record workflow updates without per-update commits

- **Reporter:** User
- **Category:** enhancement
- **Author:** Copilot

## Requirements

SDD shall persist authorized workflow record updates in the feature worktree without creating a Git commit for each update. Subsequent commands shall read the persisted updates. Concurrent record writes shall be serialized, and interrupted writes shall recover without losing or duplicating successful changes. Retain the existing bounded lock retry behavior and report lock failures explicitly.

## Acceptance Criteria

- While an authorized command records a workflow change after feature start, the system shall persist the change without creating a commit.
- When a successful workflow update is followed by another command, the system shall make the uncommitted update available to that command.
- When multiple authorized commands update workflow state concurrently, the system shall serialize the updates and retain each successful update.
- When the workflow lock cannot be acquired within bounded retries, the system shall report the failure without silently losing or overwriting records.
- When a record write is interrupted, the next workflow command shall recover it without losing a successful update or applying it twice.
- Tests shall verify these behaviors and no longer require a commit after each record update.

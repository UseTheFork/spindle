# Manage GitHub content through Blueprints

Spindle will manage GitHub content through a shared Blueprint lifecycle engine, with a static TypeScript registry and per-kind handlers; `init` and `update` remain unified, starting with Skills and adding other kinds only when ready. Versioned Blueprints own their Markdown frontmatter, parsed with `gray-matter` after Nunjucks rendering; each versioned kind stores its SemVer at `meta.spindle.version`. Just Modules are the versionless exception: they are regenerated without version metadata or conflict prompts. Each independently named module requires a shared `JUSTMODULE.just` entry; matching files in selected Stacks augment that entry rather than replace it. Rendered contributions are concatenated shared-first and then in configured Stack order, separated by a blank line. Typed TypeScript defines shared Variables and each project Config holds the user's selected Stacks and values. Duplicate output paths fail for ordinary Blueprints, while Just Module composition is an explicit exception. This is a new direction with no backwards-compatibility requirement.

# Manage GitHub content through Blueprints

Spindle will manage GitHub content through a shared Blueprint lifecycle engine, with a static TypeScript registry and per-kind handlers; `init` and `update` remain unified, starting with Skills and adding other kinds only when ready. Versioned Blueprints own their Markdown frontmatter, parsed with `gray-matter` after Nunjucks rendering; each versioned kind stores its SemVer at `meta.spindle.version`. Just Modules are the exception: they are regenerated on every `init` and `update` without version metadata or prompts. Typed TypeScript defines shared Variables and each project Config holds the user's selected Stacks and values. Shared and selected Stack overlays are combined; duplicate output paths fail for ordinary Blueprints, while Just Modules concatenate their required shared file and selected same-named Stack files in configured stack order. This is a new direction with no backwards-compatibility requirement.

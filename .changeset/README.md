# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a tool to manage versioning and changelogs. Read the full documentation at https://changesets.dev.

We also have a quick list of common questions to get you started engaging with this project in our [FAQ](https://changesets.dev/faq).

## Schema release asset

The publish workflow preserves `build/spindle.schema.json` from the pack job and validates it before publishing to npm. The build must generate this file.

After Changesets reports publishing `@use-the-fork/spindle`, `.github/scripts/publish-schema.mjs` creates or reuses the matching GitHub Release and uploads `spindle.schema.json`. This assumes a standalone package, Changesets' `v<version>` tags, and `## <version>` headings in `CHANGELOG.md`. The remote tag must resolve to the workflow commit. Missing tags, mismatched versions, invalid inputs, and GitHub API or upload failures fail the job.

Publishing to npm and uploading a GitHub asset are not atomic. If the asset upload fails after npm publication, restore the schema artifact from that run and retry the script from the same commit with `GH_TOKEN`, `GITHUB_REPOSITORY`, `GITHUB_SHA`, and the original Changesets `PUBLISHED_PACKAGES` JSON. A normal workflow rerun might report no newly published packages and skip the upload. The script reuses a matching release and replaces an existing schema asset.
